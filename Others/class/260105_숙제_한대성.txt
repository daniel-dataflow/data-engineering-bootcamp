1. Docker 이미지(Image)

정의
Docker 이미지는 컨테이너를 생성하기 위한 읽기 전용(immutable) 템플릿입니다.
애플리케이션 실행에 필요한 모든 구성 요소를 하나의 패키지로 묶은 결과물이라고 볼 수 있습니다.

포함 요소
Docker 이미지는 일반적으로 다음을 포함합니다.
-운영체제 파일 시스템 일부 (예: Alpine, Ubuntu)
-애플리케이션 실행 파일
-라이브러리 및 의존성
-환경 변수
-실행 명령(ENTRYPOINT, CMD)

특징
-불변성(Immutable)
 이미지는 생성 후 변경되지 않으며, 변경이 필요할 경우 새 이미지를 생성합니다.
-레이어 구조(Layered Architecture)
 이미지들은 여러 레이어로 구성되며, 공통 레이어는 재사용됩니다.
-재사용 가능
 하나의 이미지를 기반으로 여러 개의 컨테이너를 생성할 수 있습니다.

비유
-클래스, 설계도, 실헹파일


2. Docker 컨테이너(Container)

정의
Docker 컨테이너는 Docker 이미지가 실행된 상태의 인스턴스입니다.
즉, 이미지를 기반으로 실제 프로세스가 동작하는 환경입니다.

특징
-실행 단위(Runtime Unit)
 컨테이너는 실행 중인 애플리케이션 그 자체입니다.
-격리(Isolation)
 각 컨테이너는 독립된 파일 시스템, 네트워크, 프로세스 공간을 가집니다.
-가볍고 빠름
 VM과 달리 OS 커널을 공유하므로 오버헤드가 적습니다.
-상태(State)를 가질 수 있음
 실행 중 파일 변경, 로그 생성 등 상태 변화가 발생합니다.

비유
-객체, 실체, 실행중인 프로세서

3. CI (Continuous Integration, 지속적 통합)

정의
CI는 개발자가 작성한 코드를
공통 저장소(Git 등)에 자주 병합하고,
그때마다 자동으로 빌드와 테스트를 수행하는 방식이다.

목적
-코드 충돌을 조기에 발견
-버그를 빠르게 확인
-안정적인 코드 품질 유지

주요 흐름
-개발자가 코드 작성
-Git에 커밋 / 푸시
-CI 서버가 자동 실행
  -빌드
  -테스트
-결과 피드백 제공

CI에서 자동화되는 작업
-소스 코드 빌드
-단위 테스트(Unit Test)
-정적 코드 분석
-코드 스타일 검사

대표 도구
-Jenkins
-GitHub Actions
-GitLab CI
-CircleCI

4.CD (Continuous Delivery / Continuous Deployment)

1)Continuous Delivery (지속적 제공)

정의
테스트가 완료된 코드를
언제든지 배포 가능한 상태로 유지하는 방식이다.

특징
-배포는 수동 승인 후 진행
-운영 환경 배포 전까지 자동화

흐름
CI 완료
→ 스테이징 환경 배포
→ 운영 배포 대기 상태 유지

2)Continuous Deployment (지속적 배포)

정의
테스트를 통과한 코드를
사람의 개입 없이 자동으로 운영 환경에 배포하는 방식이다.

특징
-완전 자동 배포
-빠른 서비스 반영
-높은 자동화 성숙도 필요

흐름
CI 완료
→ 테스트 통과
→ 운영 환경 자동 배포


한 줄 요약
CI : 코드 변경을 자주 통합하고 자동으로 검증하는 것
CD : 검증된 코드를 배포까지 자동화하는 것
