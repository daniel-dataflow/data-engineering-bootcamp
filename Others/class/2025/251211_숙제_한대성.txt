1. URI (Uniform Resource Identifier)

정의:
인터넷의 자원을 식별하기 위한 포괄적 개념입니다.
URI는 두 가지 하위 분류(URN과 URL)를 포함하며, 자원을 식별만 할 수도 있고 위치를 지정할 수도 있습니다.

형식 예시:
- http://example.com/resource
- urn:isbn:9780306406157
URI는 다음 두 가지 유형 중 하나 또는 둘 모두의 특성을 가질 수 있습니다.


2. URL (Uniform Resource Locator)

정의:
자원의 위치(Location) 를 기반으로 식별합니다.
즉, 자원이 어디에 있는지 알려주며, 접근 방식(프로토콜)도 포함합니다.

구성 요소:
protocol://host:port/path?query#fragment

예시:
- https://www.example.com/index.html
- ftp://files.example.com/download.zip

특징:
- URI의 하위 개념
- 자원의 위치가 변화하면 식별자도 달라질 수 있음


3. URN (Uniform Resource Name)

정의:
위치와 무관하게 자원을 이름(Name) 으로만 식별하는 방식입니다.
자원의 위치가 바뀌어도 동일한 이름으로 계속 식별됩니다.

예시:
- urn:isbn:9780306406157 (특정 책의 ISBN)
- urn:ietf:rfc:2616 (RFC 문서 식별자)

특징:
- URI의 하위 개념
- 위치 정보 없음
- "영속적인" 식별자 개념에 가깝지만, 실제 해석 시스템은 별도로 필요함

1. 가상화(Virtualization)

가상화는 하나의 물리적 하드웨어 위에서 여러 운영체제(OS) 또는 가상 머신(VM) 을 실행할 수 있도록 하는 기술입니다.
이때 가상화를 제공하는 핵심 소프트웨어가 하이퍼바이저(Hypervisor) 입니다.
하이퍼바이저는 크게 두 가지 전가상화, 반가상화 방식으로 가상화를 제공합니다

2. 전가상화 (Full Virtualization)
정의 :
물리 하드웨어를 완전히 가상으로 에뮬레이션하는 가상화 방식입니다.
게스트 OS는 자신이 가상화된 환경에 있다는 사실을 모르고도 그대로 실행될 수 있습니다.

특징 :
게스트 OS를 수정할 필요 없음
CPU 명령과 하드웨어 접근을 하이퍼바이저가 완전히 중개
대부분의 상용 OS(Windows, Linux 등)을 그대로 실행 가능

구조 :
Hardware
   ↓
Hypervisor (에뮬레이션 + 트랩/리다이렉트)
   ↓
Guest OS (수정 불필요)

장점 :
OS 수정 없이 그대로 사용할 수 있어 호환성이 높음
다양한 OS 지원 가능

단점 :
모든 하드웨어 명령을 하이퍼바이저가 처리해야 하므로 성능 오버헤드 발생
반가상화보다 일반적으로 느릴 수 있음

대표 기술 :
VMware ESXi
Microsoft Hyper-V
KVM(기본적으로 Full 기반)

3. 반가상화 (Paravirtualization)
정의 :
게스트 OS가 가상화 환경을 인지하고 하이퍼바이저와 직접 통신하도록 OS를 수정한 가상화 방식입니다.
게스트 OS는 하드웨어 명령을 직접 실행하지 않고,
하이퍼바이저에 특수한 API(Hypercall) 로 요청합니다.

특징 :
게스트 OS가 가상화 사실을 알고 있음
OS 커널 수정이 필요함(다만 Xen PV-on-HVM 등 혼합 방식도 있음)

구조 :
Hardware  
   ↓  
Hypervisor  
   ↓  
Guest OS (하이퍼콜 지원, 수정된 커널)

장점 :
전가상화보다 오버헤드가 적어 성능이 우수
I/O 성능 향상에 유리

단점 :
OS를 수정해야 하므로 지원 OS 종류가 제한
Windows처럼 수정이 어려운 OS에는 적용하기 곤란

대표 기술 :
Xen Paravirtualization
KVM의 PV 드라이버(VirtIO)
Linux 커널의 paravirt_ops

4. 전가상화 vs 반가상화 비교

구분            전가상화 (Full)	                반가상화 (Para)
OS 수정 여부        불필요	                        필요
게스트 OS	        가상화 인지 못함	           가상화 인지함
성능	            느릴 수 있음	                더 빠름
하드웨어 접근	하이퍼바이저가 모두 에뮬레이션  	    API(하이퍼콜) 사용
호환성	                매우 높음	                제한적
대표 기술	        VMware, Hyper-V	            Xen PV, VirtIO

5. 요약
전가상화: 호환성 중심, 성능은 상대적으로 떨어짐
반가상화: 성능 중심, 오버헤드 감소, OS 수정 필요
