SQL Injection (SQLi)

1. 정의 (Definition)
SQL Injection은 해커가 웹 애플리케이션의 입력란(로그인 폼, 검색창, URL 파라미터 등)에 악의적인 SQL 구문을 주입하여, 데이터베이스가 비정상적인 동작을 하도록 조작하는 보안 취약점입니다.

2. 발생 원리 (Mechanism)
애플리케이션이 사용자의 입력을 **단순한 데이터(Data)**로 처리하지 않고, **명령어(Code)**의 일부로 해석하여 실행할 때 발생합니다.
개발자가 입력값을 검증하지 않고 SQL 쿼리 문자열에 그대로 연결(Concatenation)할 때 주로 발생합니다.

3. 대표적인 예시 (Example)

[취약한 코드 예시]
사용자 로그인을 처리하는 SQL 쿼리가 다음과 같이 작성되었다고 가정해 봅시다.
code SQL
SELECT * FROM users WHERE username = '$username' AND password = '$password';

[공격 시나리오]
해커가 아이디 입력란에 다음과 같은 값을 입력합니다.
입력값: ' OR '1'='1

[완성된 쿼리 (데이터베이스가 실행하는 것)]
code SQL
SELECT * FROM users WHERE username = '' OR '1'='1' AND password = '...';
결과: '1'='1'은 항상 **참(True)**이므로, 비밀번호를 몰라도 WHERE 절이 통과되어 로그인에 성공하게 됩니다.

4. 주요 피해 영향 (Impact)
인증 우회: 관리자 계정 등 타인의 계정으로 로그인 가능.
데이터 유출: 회원 정보, 개인정보, 비밀번호 등 DB 내 중요 정보 탈취.
데이터 변조 및 삭제: 데이터베이스 내용을 수정(UPDATE)하거나 삭제(DELETE, DROP)하여 서비스 마비.
시스템 장악: 데이터베이스 설정에 따라 운영체제(OS) 명령어까지 실행하여 서버 전체 장악 가능.

5. 공격 유형 (Types)
Error-Based SQLi: DB 에러 메시지를 유발하여 데이터베이스 구조 정보를 파악.
Union-Based SQLi: UNION 연산자를 사용해 원래 쿼리의 결과에 다른 테이블의 데이터를 합쳐서 유출.
Blind SQLi: 에러나 데이터가 화면에 출력되지 않을 때, 쿼리의 참/거짓 결과(Boolean-based)나 응답 시간(Time-based)을 통해 데이터를 한 글자씩 알아내는 방식.

6. 대응 및 예방 방안 (Prevention) - 가장 중요
① Prepared Statement (파라미터화 된 쿼리) 사용
가장 효과적인 방어법입니다.
SQL 쿼리 틀을 미리 컴파일해두고, 사용자의 입력값은 오직 **데이터(매개변수)**로만 처리합니다.
입력값에 ' OR '1'='1이 들어와도 명령어가 아닌 단순 문자열로 인식됩니다.
예: Java (JDBC), PHP (PDO), Python (Cursor) 등에서 ? 또는 :param 바인딩 사용.

② 입력값 검증 (Input Validation)
사용자 입력값에 특수문자(', ", -, ; 등)가 포함되어 있는지 검사하거나 제거(Sanitizing)합니다.
숫자 필드에는 숫자만 들어오도록 타입을 강제합니다.

③ ORM (Object Relational Mapping) 사용
JPA, Hibernate, Django ORM, Sequelize 등 검증된 프레임워크를 사용하면 내부적으로 SQL Injection을 방어하는 메커니즘이 포함되어 있어 안전합니다.

④ 최소 권한 원칙 (Least Privilege)
웹 애플리케이션이 사용하는 DB 계정에 sa나 root 같은 최고 관리자 권한을 주지 않습니다.
해당 서비스에 필요한 테이블에만 접근 권한(SELECT, INSERT 등)을 부여합니다.


요약
SQL Injection은 입력창에 SQL 명령어를 넣어 DB를 조작하는 해킹 기법입니다. 이를 막기 위해서는 반드시 Prepared Statement(파라미터 바인딩) 방식을 사용하여 입력값이 명령어로 실행되지 않도록 해야 합니다.
