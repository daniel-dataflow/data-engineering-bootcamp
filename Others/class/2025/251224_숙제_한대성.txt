1. DAG의 정의

DAG는 Directed Acyclic Graph의 약자로,
작업(Task) 간의 실행 순서와 의존성을 방향성 있는 비순환 그래프로 표현한 구조이다.

-Directed (방향성)
작업 간 실행 순서가 정해져 있음
예: A → B (A 실행 후 B 실행)

-Acyclic (비순환)
순환 구조 불가
예: A → B → A 는 허용되지 않음

-Graph (그래프)
노드(Node) = Task
엣지(Edge) = Task 간 의존성


2. Airflow에서 DAG의 역할

DAG는 데이터 파이프라인의 설계도 역할을 하며, 다음을 정의한다.

-어떤 작업들이 존재하는지
-작업 간 실행 순서
-실행 주기(스케줄)
-재시도 정책
-병렬 실행 가능 여부

즉, Airflow는 DAG에 정의된 내용만을 기준으로 작업을 실행한다.


3. DAG의 주요 구성 요소

1)DAG 객체
-DAG 전체의 메타데이터를 관리
-DAG ID
-시작 날짜(start_date)
-스케줄(schedule_interval)
-기본 옵션(default_args)

2)Task

-DAG 안에서 실행되는 최소 작업 단위
-Operator를 통해 정의됨
	대표적인 Operator 예시
		-BashOperator
		-PythonOperator
		-SparkSubmitOperator
		-KubernetesPodOperator

3)Dependency (의존성)

-Task 간 실행 순서를 정의
-선행 작업이 완료되어야 다음 작업이 실행됨


4. DAG와 Task Instance의 차이

DAG

-워크플로우의 설계도
-코드로 정의됨
-실제 실행 단위는 아님

Task Instance

-DAG가 특정 시점(execution_date)에 실행된 결과
-실제 실행되는 객체
-실행 날짜 개념을 가짐


5. DAG 실행과 시간 개념

execution_date는 실제 실행 시간이 아니라,
“처리해야 할 데이터의 기준 시간”을 의미한다.

예:

-daily 스케줄
-2024-01-02 00:00 실행
→ 2024-01-01 날짜의 데이터를 처리


6. DAG 설계 시 기본 원칙

-DAG는 멱등성(Idempotency)을 가져야 함
 동일 DAG를 여러 번 실행해도 결과가 동일해야 함
-Task는 가능한 한 작게 분리
 실패 시 재시도와 병렬 처리에 유리
-순환 구조는 절대 불가
 DAG 파싱 단계에서 오류 발생


7. 요약

-DAG는 작업 흐름을 그래프 구조로 정의한 것
-Airflow의 모든 스케줄링과 실행은 DAG를 기준으로 동작
-ETL, 데이터 파이프라인, ML 워크플로우의 핵심 구성 요소
