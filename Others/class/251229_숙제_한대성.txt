서버 통신 시 직렬화(Serialize)가 필요한 이유

1. 직렬화의 정의

직렬화란 메모리에 존재하는 객체(구조체, 클래스 등)를
네트워크로 전송 가능한 바이트 스트림 형태로 변환하는 과정이다.

수신 측에서는 역직렬화(Deserialize)를 통해 원래 구조로 복원한다.

2. 메모리 객체는 그대로 전송할 수 없음

객체는 메모리 주소, 포인터, 참조를 포함

프로세스 내부에서만 의미가 있음

다른 서버/프로세스에서는 주소와 구조가 무의미
→ 메모리 객체를 그대로 네트워크로 보낼 수 없음

3. 네트워크는 바이트 스트림만 전송 가능

TCP/IP, HTTP 등 모든 네트워크 통신은 바이트 단위로 동작

객체, 리스트, 클래스 개념은 네트워크에 존재하지 않음
→ 바이트로 변환 필요 = 직렬화

4. 언어·플랫폼 독립성 확보

서로 다른 언어(Python, Java, C++)

서로 다른 OS, CPU 아키텍처(x86, ARM)

메모리 표현 방식이 모두 다름
→ 공통 포맷(JSON, Protobuf 등)으로 변환 필요

5. 데이터 구조와 의미 보존

단순 문자열 전송은 의미 해석이 어려움

직렬화 포맷은 필드명, 타입, 계층 구조를 포함
→ 데이터의 의미를 함께 전달 가능

6. 메시지 경계(Boundary) 문제 해결

TCP는 메시지 개념이 없는 스트림 통신

데이터의 시작과 끝이 불명확
→ 직렬화 포맷이 메시지 구조와 길이를 명확히 정의

7. 저장·재전송·복원 가능

직렬화된 데이터는 파일, 로그, 메시지 큐, 캐시에 저장 가능

동일 포맷으로 전송·저장·복원이 가능
→ 일관된 데이터 처리 가능

8. 직렬화를 사용하지 않을 경우 문제점

포인터/주소 값 전송 → 의미 없음

언어 간 통신 불가

데이터 구조 해석 오류

메시지 파싱 오류

버전 변경 시 호환성 문제

9. 대표적인 직렬화 포맷

JSON: 가독성 좋음, 속도 느림 (REST API)

XML: 구조적이나 무거움 (레거시)

Protobuf: 바이너리, 빠름 (gRPC)

Avro: 스키마 중심 (Kafka)

Thrift: IDL 기반 RPC

10. 한 줄 요약

직렬화는 메모리 객체를 네트워크에서 이해 가능한 형태로 변환하기 위한 필수 과정이다.
