1. 403 Forbidden : 클라이언트는 콘텐츠에 접근할 권리를 가지고 있지 않습니다. 예를들어 그들은 미승인이어서 서버는 거절을 위한 적절한 응답을 보냅니다. 401과 다른 점은 서버가 클라이언트가 누구인지 알고 있습니다.

2. 404 Not Found : 서버는 요청받은 리소스를 찾을 수 없습니다. 브라우저에서는 알려지지 않은 URL을 의미합니다. 이것은 API에서 종점은 적절하지만 리소스 자체는 존재하지 않음을 의미할 수도 있습니다. 서버들은 인증받지 않은 클라이언트로부터 리소스를 숨기기 위하여 이 응답을 403 대신에 전송할 수도 있습니다. 이 응답 코드는 웹에서 반복적으로 발생하기 때문에 가장 유명할지도 모릅니다.

3. CDN (Content Delivery Network, 콘텐츠 전송 네트워크)
CDN은 지리적으로 분산된 서버들의 네트워크로, 사용자가 웹 콘텐츠(HTML, 이미지, 동영상, JS 파일 등)를 요청했을 때 사용자와 가장 가까운 서버(Edge Server)에서 콘텐츠를 전송하여 로딩 속도를 획기적으로 높이는 기술입니다.

핵심 작동 원리
- Origin Server (원본 서버): 웹 서비스의 실제 데이터가 저장된 메인 서버입니다.
- Caching (캐싱): 전 세계 곳곳에 위치한 **Edge Server(에지 서버)**가 원본 서버의 정적 파일들을 미리 저장(캐싱)해 둡니다.
- Routing (라우팅): 사용자가 URL에 접속하면, DNS가 사용자의 위치와 가장 가까운(네트워크 지연 시간이 가장 짧은) 에지 서버로 연결합니다.
- Delivery (전송):
  -- Cache Hit: 에지 서버에 데이터가 있다면 즉시 사용자에게 전송합니다.
  -- Cache Miss: 데이터가 없다면 에지 서버가 원본 서버에서 데이터를 가져와 저장한 후 사용자에게 전송합니다.

주요 이점
- 지연 시간(Latency) 감소: 물리적 거리가 줄어들어 데이터 전송 속도가 빨라집니다.
- 트래픽 분산: 원본 서버로 집중되는 트래픽을 분산시켜 서버 부하를 줄이고 다운되는 것을 방지합니다.
- 보안 강화: DDoS 공격 등이 발생했을 때 거대한 네트워크 용량으로 트래픽을 흡수하여 원본 서버를 보호합니다.

4. DOMContentLoaded는 웹 브라우저가 페이지를 로드하는 과정에서 발생하는 특정 이벤트(Event) 시점을 의미합니다.

정확한 정의
- 브라우저가 초기 HTML 문서를 완전히 불러오고 분석(Parsing)하여 DOM 트리(DOM Tree) 생성을 완료했을 때 발생합니다.
- 핵심 차이점: CSS, 이미지, 하위 프레임(Subframe) 등의 외부 리소스가 로딩 완료되는 것을 기다리지 않습니다.

★서비스★
DOMContentLoaded vs load (window.onload) 비교

A. 핵심 요약
DOMContentLoaded: HTML만 다 읽으면 실행 (빠름)
load (window.onload): 이미지, CSS 등 모든 걸 다 가져오면 실행 (느림)

B. 상세 비교

[발생 시점]
DOMContentLoaded: 브라우저가 HTML을 파싱하여 DOM 트리를 완성한 즉시 발생합니다. 이미지나 스타일시트 로딩은 기다리지 않습니다.
load: HTML뿐만 아니라 이미지, 스타일시트, 스크립트 등 포함된 모든 외부 리소스가 화면에 로드된 후에 발생합니다.

[실행 속도]
DOMContentLoaded: 빠릅니다. (사용자가 내용을 인식하는 시점과 유사)
load: 느립니다. (모든 데이터가 도착해야 함)

[주요 용도]
DOMContentLoaded: DOM 요소를 제어하는 스크립트 실행, 버튼 클릭 이벤트 등록 등
load: 이미지 사이즈를 계산해야 하는 작업, 로딩 스피너 제거, 외부 리소스가 꼭 필요한 로직

C. 개발 팁
<script defer>를 사용하면 DOMContentLoaded 발생 직전에 스크립트가 실행되어 렌더링을 방해하지 않습니다.
